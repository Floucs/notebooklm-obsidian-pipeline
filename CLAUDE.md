# Claude Code — NotebookLM Obsidian Pipeline

## Project Overview

This repository contains an automated pipeline that processes academic lecture
materials (PDFs + optional transcripts) through NotebookLM and writes structured
Markdown notes into an Obsidian vault.

**Stack:**
- Python 3.10+ (`ingest.py`, `batch_ingest.py`, `config.py`)
- `notebooklm-py` CLI (Playwright-based, Google account auth required)
- Obsidian vault with Dataview, Templater, Kanban, Annotator, Obsidian Git

## Vault Structure

```
MasterVault/
├── 00_INBOX/       ← Pipeline output lands here (status: raw)
├── 10_LECTURES/    ← Manually reviewed lecture notes
├── 20_CONCEPTS/    ← Atomic concept notes (Zettelkasten style)
├── 30_EXAMS/       ← Exam preparation material
├── 40_RESOURCES/   ← Literature and external links
├── 90_TEMPLATES/   ← Obsidian Templater templates
└── _PIPELINE/      ← Python scripts (this repo)
```

## Note Format

Every generated note follows this YAML frontmatter schema:

```yaml
title: "Lecture 01 - Topic Name"
module: "CS-101"
lecture_nr: 01
date: YYYY-MM-DD
professor: ""
tags:
  - lecture
  - cs101
status: "raw"          # raw → reviewed → done
source_pdf: "file.pdf"
source_transcript: ""
notebooklm_id: "uuid"
annotation-target: "C:/path/to/file.pdf"   # for Obsidian Annotator
```

## Status Workflow

`raw` → `reviewed` → `done`

- **raw**: freshly generated by pipeline, not yet manually checked
- **reviewed**: human has read and corrected the note
- **done**: note is complete, cross-linked, and exam-ready

## How Claude Should Help

When assisting with this project, Claude should:

### Code tasks
- Prefer editing existing scripts over creating new ones
- Keep `ingest.py` and `batch_ingest.py` cross-platform (Windows/macOS/Linux)
- Use `Path` objects throughout, never string concatenation for file paths
- Always import config values from `config.py`; never hardcode paths
- Maintain the 5-step pipeline structure: create → upload → wait → query → write

### Note content tasks
When reviewing or improving generated notes:
- Extract **exam-relevant** key points — not everything, just what gets tested
- Define terms **concisely**: one sentence definition, optional second sentence for context
- Summaries should be **5–8 sentences**, factual, no padding
- Connections should reference **specific other modules or lectures** when identifiable
- Flag empty or low-quality sections rather than filling them with filler text

### Obsidian formatting rules
- Use `[[double brackets]]` for internal wiki links to other notes
- Use `#tag` in body sparingly; prefer YAML frontmatter tags
- Never leave section headers without at least one line of content
- Checkboxes in Open Questions: `- [ ] Question text`

### Language handling
- Source material may be in English or German
- Query language is controlled by `DEFAULT_LANGUAGE` in `config.py`
- Section headers auto-switch based on language setting
- Never mix languages within a single note

## Key Files

| File | Purpose |
|------|---------|
| `config.py` | User-editable: vault path, language, source folder |
| `ingest.py` | Single PDF → NotebookLM → Obsidian note |
| `batch_ingest.py` | Whole folder → multiple notes |
| `obsidian-templates/tpl_lecture_note.md` | Templater template for manual notes |
| `obsidian-templates/tpl_concept_note.md` | Templater template for concept notes |

## Common Commands

```bash
# Single PDF
python ingest.py --pdf "Lecture01.pdf" --module "CS-101"

# With transcript
python ingest.py --pdf "Lecture01.pdf" --transcript "Lecture01.txt" --module "CS-101"

# Whole folder
python batch_ingest.py --folder "C:/Lectures/CS-101" --module "CS-101"

# Dry run (preview only)
python batch_ingest.py --folder "C:/Lectures" --module "CS-101" --dry-run
```

## Conventions

- All notes on a consistent level: Master's / PhD academic standard
- No filler phrases ("In conclusion…", "This is important because…")
- Definitions use the format: **Term**: explanation
- Bullet points preferred over long paragraphs in key points sections
